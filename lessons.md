# Lessons

Append-only. The agent appends after every resolution; humans prune.

Format: `date | class | symptom | root cause | fix | gotcha`

Seeded from failures that occurred while the system was being built, dated by
the commit that fixed each one. They are here because they are the failure modes
this system actually has, and because a pattern appearing three or more times
below is a promotion candidate for `skills/triage/references/`.

- 2026-08-30 | deploy-regression | Deploy built, migrated and served correctly, then failed its own smoke test with a 404 on `/healthz` | Cloud Run's Google Frontend intercepts that exact path and never forwards it; the 404 body was Google's page, not FastAPI's | Renamed the endpoint to `/health` and added a regression test asserting the path | Probe the boundary before blaming the app — `/health`, `/livez` and `/readyz` all pass through, only `/healthz` is swallowed. A 404 from an endpoint you can see in the router means something in front of the app answered.
- 2026-08-30 | pipeline-gap | Events published successfully but never appeared in BigQuery. No error, no dead letter | A Pub/Sub BigQuery subscription silently discards messages targeting a `JSON`-typed column | Changed `payload` to `STRING` and wrapped it in `PARSE_JSON()` in the views | Isolated by publishing a payload-free event, which landed instantly. When something is missing rather than broken, bisect the message, not the code.
- 2026-08-30 | pipeline-gap | A single publish landed in BigQuery twice under one `event_id` | Pub/Sub delivery is at-least-once; this is correct behaviour, not a fault | None — every view and consumer dedupes on `event_id` | Dedupe is a requirement, not a precaution. It was observed in practice within the first day of the topic existing.
- 2026-08-30 | dependency-outage | Session exchange returned a generic 401 with no explanation | The API service account lacked `roles/firebaseauth.admin`; the underlying `INSUFFICIENT_PERMISSION` was being swallowed | Granted the role, and logged the underlying exception | The fix was only findable after adding the log line. An IAM change presents exactly like an outage and is far more likely in a young project.
- 2026-08-30 | pipeline-gap | Table-scoped BigQuery IAM vanished whenever the table was replaced | Grants scoped to a table are destroyed with it | Kept table scope and bound it with `replace_triggered_by` on the table resource, then proved it by forcing a replacement and re-publishing | Dataset scope would have been easier and was flagged in security review as too broad. Prove the narrow fix instead of widening the grant.
- 2026-08-31 | deploy-regression | Signed upload URLs named `smoodie-local-media` in the deployed service | `SMOODIE_MEDIA_BUCKET` was never set on Cloud Run; the app fell back to its local default | Set the variable in Terraform | The tests use a fake object store and structurally cannot observe this. A green suite says nothing about deployed configuration — read the running service's env.
- 2026-08-31 | error-spike | Invalid recipes returned validation errors from both union branches, and the OpenAPI schema emitted a bare `anyOf` | FastAPI's `Body()` wrapper overrode `Field(discriminator=...)`, so Pydantic fell back to trying every branch | Removed the wrapper; two tests pin the behaviour and the published schema | The suite was green throughout. The schema is part of the contract — assert on it, not only on responses.
- 2026-08-31 | error-spike | `PATCH` on a recipe returned three ingredients when two were sent; the database held the correct two | Replacing the ingredient set uses bulk deletes, which bypass the identity map, and the session sets `expire_on_commit=False`, so the re-read returned the pre-edit collection | `session.expunge_all()` before re-reading | `expire_all()` is the obvious fix and is wrong: an expired attribute refreshes lazily, and a lazy refresh cannot run on an async session — it turned 20 passing tests into `MissingGreenlet` failures. Also: the original test asserted against the database, so it could not see a stale *response*.
- 2026-08-31 | deploy-regression | Rolling a migration back and reapplying it failed with "type already exists" | An already-shipped migration created a Postgres enum type but never dropped it on downgrade | Patched the downgrade to drop the type | Found only by testing the downgrade path. Forward-only testing hides rollback bugs, and rollback is the thing you need most under pressure.
